# HarmonyOS 智能家居车载端

> 基于 HarmonyOS NEXT 的智能座舱应用，让驾驶者通过语音一句话控制全屋设备，实现"车家互联"的无缝体验。

---

## 📖 项目概述

本项目是专为智能汽车座舱打造的 HarmonyOS 应用，采用 **ArkTS** 开发，面向 **car** 设备类型。它将智能家居控制与车载场景深度融合，通过**悬浮语音助手**、**场景联动**、**GPS 定位**等能力，让用户在驾驶途中安全、便捷地管理家中设备。

| 项目信息 | 说明 |
|---------|------|
| **开发语言** | ArkTS（.ets） |
| **目标设备** | 智能座舱（car） |
| **UI 框架** | ArkUI（声明式） |
| **语音能力** | 原生 SpeechKit（ASR + TTS） |
| **网络通信** | HTTPS + CA 证书验证 + 防重放安全头 |
| **定位服务** | GPS + 逆地理编码 |

---

## 🚀 核心功能

### 1. 车载语音助手（CarVoiceAssistant）

- **唤醒词**：说出"小华"激活助手，表情从 `sleep` 切换为 `smile`
- **语音识别**：基于鸿蒙原生 `speechRecognizer` 持续监听，识别用户指令
- **意图识别**：双引擎（LLM 通义千问 + 本地关键词）支持 14 种意图类型，包括设备控制、场景触发、导航、查询、闲聊等
- **语音播报**：原生 `textToSpeech` 实时合成回复，无需下载音频文件
- **悬浮可拖拽**：组件常驻右下角，拖拽位置自动记忆，不遮挡主交互

### 2. 场景联动（一句话回家/离家）

车载端独有场景联动能力，用户只需一句话即可触发全屋设备联动：

| 场景 | 触发语句示例 | 执行动作 |
|------|------------|---------|
| **回家模式** | "我快到家了"、"我回来了" | 自动打开所有灯 + 打开所有空调（并恢复每个空调上次使用的温度/模式/风速） |
| **离家模式** | "我要出门了"、"我走了" | 自动关闭所有在线灯和空调（跳过已离线设备） |

> 💡 **习惯智能**：回家模式会从服务器获取空调的历史设置，自动恢复用户习惯（温度、模式、风速），无需重复设定。

### 3. 横屏三栏设备控制（DevicePage）

针对车载横屏优化，将灯光、空调、门锁三类设备同屏展示：

- **左栏**：灯光列表（按房间分组，支持批量开关）
- **中栏**：空调控制面板（温度调节、模式切换、风速、扫风/睡眠/节能）
- **右栏**：门锁列表（支持开关，含门禁状态检测）

所有操作均采用**乐观更新**（UI 先变，API 失败后回滚），交互更流畅。

### 4. GPS 定位服务（LocationUtil）

- 精确定位车辆当前位置（经纬度 + 逆地理编码地址）
- 60 秒缓存机制，避免频繁 GPS 请求
- 定位结果自动注入语音助手聊天上下文，为场景联动提供位置基础（未来可扩展"离家 5 公里自动关灯"等）

### 5. 安全通信

- **HTTPS + CA 证书验证**：从 rawfile 加载自签名根证书，验证服务器身份
- **防重放安全头**：每个请求携带 `X-Request-ID`、`X-Timestamp`、`X-Nonce` 等头，后端可防重放攻击
- **加密随机数生成**：使用鸿蒙 `cryptoFramework` 生成安全随机数，降级方案兜底

## 🛠️ 快速开始

### 环境要求
- DevEco Studio NEXT 及以上
- HarmonyOS SDK 对应 API 版本
- 真机或模拟器（车载/平板，语音功能需真机支持）
- 后端服务（Flask API，需提供设备控制、空调状态等接口）

### 配置
1. 修改 `ApiClient.ets` 中的后端地址（默认 `http://YOUR_BACKEND_HOST:5001/api`）
2. 将自签名 CA 证书 `rootCA.crt` 放入 `rawfile` 目录
3. 确保 `module.json5` 已声明所需权限（INTERNET、MICROPHONE、LOCATION 等）

### 编译运行
1. 在 DevEco Studio 中打开项目
2. 连接真机或启动模拟器
3. 点击运行，应用将安装到设备

## 🔌 API 接口摘要（后端需提供）

| 接口 | 方法 | 用途 |
|------|------|------|
| `/api/device/list` | GET | 获取用户所有设备（灯/空调/门） |
| `/api/device/control` | POST | 控制单个设备（开关/参数） |
| `/api/device/ac/{deviceId}` | GET | 获取空调详细状态（含历史设置，用于习惯恢复） |
| `/api/device/lights?homeId={id}` | GET | 获取灯光列表 |
| `/api/device/messages` | GET | 获取消息列表 |

**请求头**：所有请求均携带 `Authorization: Bearer <token>` 以及防重放安全头（详见 `RequestSecurityUtil`）。

---

## 🔐 安全机制

- **CA 证书验证**：应用启动时将 rawfile 中的 `rootCA.crt` 复制到沙箱，后续 HTTPS 请求设置 `caPath`，验证服务器证书合法性。
- **防重放头**：每次请求生成 `X-Request-ID`（时间戳+随机数）、`X-Timestamp`、`X-Nonce`（16 字节加密随机数），后端可基于时间窗口和 Nonce 去重。
- **加密随机数**：优先使用 `cryptoFramework.createRandom()`，失败时降级为时间戳+计数器。

## ✨ 项目亮点

1. **"一句话回家"场景联动**：语音触发回家/离家模式，自动控制全屋设备，并恢复空调历史习惯，真正无感化。
2. **横屏三栏设备控制**：针对车载横屏优化，灯/空调/门同屏展示，操作高效。
3. **悬浮语音助手**：可拖拽、状态反馈（待机/激活），不干扰驾驶视线。
4. **双引擎意图识别**：LLM 保证高准确率，本地关键词作为兜底，离线场景依然可用。
5. **GPS 位置感知**：定位数据注入助手上下文，为未来基于位置的自动化提供基础。
6. **企业级安全**：CA 证书验证 + 防重放请求头，保障车机与云端通信安全。
